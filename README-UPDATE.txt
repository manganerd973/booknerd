BOOKNERD — восстановление профиля и ответы администратора

Этот архив включает предыдущее исправление Cloudflare/главной. Установите его ПОСЛЕ прежних архивов, не заменяйте затем старой версией.
Распакуйте содержимое в C:\Users\HP\Documents\GitHub\booknerd с заменой файлов и сохранением вложенных папок. GitHub Desktop: Commit → Push origin. Дождитесь успешного развёртывания Cloudflare. На живом сайте эти изменения ещё не опубликованы нами.

ПРОФИЛЬ
После установки обновления откройте свой существующий профиль → Сохранить доступ к профилю → Получить код восстановления. Скопируйте его в надёжное место ВНЕ приложения. Код является секретом: любой, у кого он есть, может открыть этот профиль. После переустановки: профиль → Вернуть прежний профиль → вставить код → Восстановить профиль.
Восстанавливается тот же серверный идентификатор и связанные данные: личная библиотека, профиль, серверная статистика. Данные разных профилей не объединяются. Офлайн-книги, локальные выделения, настройки устройства и старые голоса с отдельным локальным ключом в этот механизм не входят. Код нельзя получить задним числом после полной потери старой идентичности. Пароль владельца должен быть настроен; при его изменении ранее выданные коды перестают действовать. Для обычного удаления ярлыка данные иногда сохраняются, но полагаться на это нельзя.
Коды подписаны сервером, не создают дополнительную таблицу и не запускают фоновые запросы.

ОТВЕТЫ BOOKNERD
Войдите как владелица: админка → Комментарии и отзывы → под опубликованным комментарием «Ответить как Администратор BOOKNERD». Введите текст, при необходимости отметьте спойлер, отправьте. Ответ появится в ветке комментария с серверной отметкой администратора. Для скрытого комментария сначала нажмите «Вернуть на сайт». Ответы на отдельные книжные отзывы пока не добавлены.
Добавляется один столбец comments.is_admin, существующие комментарии сохраняются. Версия схемы обновлена, повторная миграция не запускается на каждом открытии.

ПРОВЕРКИ
Production build прошёл. Проверены код восстановления и отклонение подделок, обязательный вход владельца, проверка длины ответа, проверка родительского комментария и запись официального ответа. Реальный вход на ваших устройствах требует проверки после публикации.

Вернули конфигурацию из истории проекта 334929a: фоновые публикации раз в 5 минут; ежемесячный обработчик читательских уровней; прежнюю дату совместимости; заголовки обновления service worker. Имя Worker и идентификатор D1 сохранены. Новые базы и бакеты не создаются.

Добавлена проверка суммарного объёма изображений в D1 (book_covers и reader_avatar_images) перед загрузкой: бюджет 64 МиБ. Это защитный порог приложения, не квота Cloudflare и не ограничение всей базы. При превышении новая загрузка отклоняется, сохранённые данные не удаляются. Проверка выполняется только при загрузке изображения. Одновременные загрузки могут немного превысить порог. Ранее сохранённые файлы автоматически не очищаются. При достижении порога требуется пересмотр хранения администратором. Изображения в отдельно подключённом R2 этим порогом не ограничиваются.

Проверено: production build, проверки границы бюджета и ошибок базы, проверки предыдущего hotfix. Живой сайт и квоты аккаунта после установки необходимо проверить отдельно. База может расти за счёт глав, комментариев и истории: этот архив не гарантирует, что хранилище никогда не заполнится.
